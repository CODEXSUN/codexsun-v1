# Data Migration 1.1.55: production API proxy repair

## Problem and fix

Database Settings requests `/api/data-migration/sources`.
The production web configurations lacked routes for this API prefix.
Those requests could reach the SPA fallback and return HTML with HTTP 200.
The frontend then reported `Unexpected token '<'` when it tried to parse JSON.
Data Bridge requests used another missing prefix with the same routing problem.

The CODEXSUN, Billing, and demo Nginx templates now forward both DevKit prefixes to Platform.
They preserve `/api/data-migration` and `/api/data-bridge` because the upstream routes already contain `/api`.
Existing `/api/platform` and `/api/app` rewrites remain unchanged.
Query strings, POST payloads, authentication cookies, and tab-slot headers pass through.

The Data Migration client checks content type, JSON parsing, and response envelopes.
Non-JSON responses and unavailable gateways produce useful diagnostics without exposing response bodies.
Normal API errors retain their request IDs.

## Verified locally

- Seven frontend tests cover source lookup, mutations, tab authentication, HTML, gateway failures, malformed JSON, and server errors.
- One real local Nginx test covers all three production web templates.
- The negative fixture reproduces the original HTML fallback after removing the routing repair.
- The repaired templates return JSON and preserve request paths, query strings, POST methods, bodies, and authentication context.
- Existing API aliases and SPA navigation still work.
- A separate local smoke check reaches the actual Platform API through Nginx.
- Both protected source endpoints return HTTP 403 JSON for unauthenticated requests rather than HTML.
- Data Migration and Platform web typechecks and the Platform web production build passed before this version-only release step.
- The Data Migration boundary check and dependency layout check passed.

The Nginx tests used a native local executable and disposable loopback ports.
Docker was unavailable, so a Linux container deployment was not tested.
The full shared-workspace check encountered unrelated unfinished Codeit module roles.
Release documentation is generated and checked against the staged release files separately.
Unrelated Core, Codeit, and ecommerce changes are excluded from this commit.

## Deployment ownership

This release changes proxy configuration and frontend response handling only.
It adds no database migration and changes no business records or connection credentials.
The operator owns cloud deployment.
Rebuild and deploy the web image to apply its Nginx template and frontend bundle changes.
Reloading the existing browser page alone cannot update the deployed proxy configuration.
No VPS configuration, remote database, or running cloud service was changed during this repair.
