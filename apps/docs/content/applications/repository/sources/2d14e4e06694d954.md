# Codeit

Codeit is a standalone development workspace in `devkits/codeit`.

Run `npm run dev -w @codexsun/codeit` from the repository root. The app listens on `127.0.0.1:7070` by default. Set `CODEXSUN_CODEIT_WEB_PORT` to choose another port.

## Prompt Manager

Open `/codeit/prompt-manager` to create, view, edit, suspend, restore, and search saved prompts.
The list uses the shared CRM workspace controls, column search, date ranges, and pagination.
Choose a Codex chat on the show page, review the saved text, and select **Send prompt**.
Each run stores the sent text, destination, status, final response, timestamps, and activity.
Editing a saved prompt does not change earlier runs. Prompts with run history cannot be permanently deleted.

The local API uses `/api/codeit/prompt-manager` on the same Vite listener. It runs in development
and Vite preview. Its SQLite database is `storage/codeit/prompt-manager.sqlite` in this checkout.
It contains personal prompts and responses; keep it outside Git and back it up as local data.
There are no example prompts, tenant databases, automatic sends, or background schedules.

Install the Codex CLI and sign in with `codex login` before connecting. CodeIt starts a local
`codex app-server --stdio` client using the current OS account. It lists the 100 most recently
updated local Codex chats, resumes the selected chat, starts one turn, and records completion events.
The connection uses the permissions already configured in Codex.
Each run uses its own Codex connection. CodeIt closes that connection after saving a terminal result,
so the desktop app can reopen the chat. Other running chats keep their own connections.
Command and file-change approval
requests appear on the run card for an explicit approve/decline decision. Unsupported interactive
requests are rejected; continue those workflows in Codex. ChatGPT cloud conversations are not supported.

Run status is updated while the local server is running. Browser navigation does not stop a run.
CodeIt shows completion and approval alerts while its browser page is open.
When the server restarts, unconfirmed runs become **Interrupted**. Check the destination chat before
resending; CodeIt never retries a prompt automatically. Another Codex client may also be using the
same chat, so avoid sending to a chat that is already running elsewhere.

The API accepts only the configured loopback host and same-origin browser requests. Writes require
the CodeIt request header. Keep this listener local; the static web bundle alone cannot provide storage
or a Codex connection. A hosted or multi-user API requires a separate authentication and runtime design.
