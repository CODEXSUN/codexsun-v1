# Sportsclub Skills and Guidelines

Use this guide for planning, developing, reviewing, and maintaining the `apps/sportsclub` application. Read `apps/sportsclub/agent/TASK.md` for current work items and `apps/sportsclub/agent/PLAN.md` for architectural specifications.

Documentation never grants runtime permissions. A prompt, tenant setting, or note must never weaken a backend permission check.

## Working Rules

1. **Multi-Tenancy and Isolation**:
   - Every database query must execute against the authenticated tenant's database.
   - Never accept tenant IDs, database names, or role parameters from the browser query or body.
   - Tenkasi Sports is a dedicated tenant (`TENKASISPORTS`) with isolated persistence.

2. **Module-Owned CRUD Standard**:
   - Backend modules implement the 8-file pattern (`migration.ts`, `module.ts`, `repository.ts`, `routes.ts`, `seed.ts`, `service.ts`, `types.ts`, `index.ts`).
   - Frontend modules implement the 8-file pattern (`workspace.tsx`, `list.tsx`, `form.tsx`, `services.ts`, `hooks.ts`, `schema.ts`, `types.ts`, `index.ts`).
   - Use `registerContractRoute()` with strict Zod schemas for all backend routes. Do not use direct request body casts.
   - Do not pass unrecognized keys into strict schemas on update.

3. **Content and Asset Fidelity**:
   - Use the exact approved logo from `C:/Users/sunda/Desktop/veera/logo.jpeg`.
   - Use the approved name: வீரத்தமிழன் பாரம்பரிய சிவகலை குருகுலம் (Veerathamilan Traditional Sivakalai Gurukulam).
   - Use verified curriculum and historical origins from the Silambam student handbook authored by Asan T. Veerapandian.
   - Strict rule: Do not invent credentials, awards, medical claims, fees, schedules, or physical addresses.

4. **Forbidden Patterns**:
   - Never place sports club management business logic inside `apps/sites`. Sites is reserved for public site rendering and deployment artifacts.
   - Never introduce generic CRUD shells, dynamic table names, or metadata-driven field dictionaries.
   - Never bypass Platform role authorization checks.
   - Never reintroduce redundant tenant columns where tenant databases are isolated.

## Verification Checklist

For a small change, inspect the affected code and use at most one focused check when useful.
Inspection can suffice for a trivial edit. Add checks when the actual risk requires them.
Use the following checklist for a full audit or release, not for each change:

1. Run TypeScript typecheck: `npm run typecheck -w @codexsun/sportsclub-api -w @codexsun/sportsclub-web`.
2. Run linter: `npm run lint -w @codexsun/sportsclub-api -w @codexsun/sportsclub-web`.
3. Run module boundary audit: `node tools/check-module-boundaries.mjs sportsclub`.
4. Run component documentation audit: `npm run check:component-docs` and `npm run test:component-docs`.
5. Run unit and integration tests with temporary isolated databases.
6. Report skipped checks and environmental dependencies honestly.
