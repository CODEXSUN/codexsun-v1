# cxmobile architecture and planning audit

## Audit result

Audit date: 25 October 2026. Scope: documentation, contract analysis, and read-only source inspection across CRM, Billing, Chat, Ecommerce, Core, and Platform.
The selected React + Capacitor direction fits the existing React owner screens and composed Platform API.
This audit completes the M0 inventory and contract analysis. All implementation phases remain open.

The audit changed documentation only within its assigned write lease (`apps/cxmobile/agent/TASK.md` and `apps/cxmobile/agent/AUDIT.md`).
No native projects were generated, no dependencies were installed, no production databases or APIs were altered, and existing unrelated changes remain preserved.

## Findings and planned resolution (A01–A15)

Priority describes implementation impact. Resolved wording means the plan and contract baseline address the issue, not that runtime code fixes exist.

| ID  | Priority | Finding and source evidence                                                                                                                                                                                              | Planned resolution                                                                                                                                                                                                                                                                                    | Runtime state  |
| --- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------- |
| A01 | High     | Platform Web (`apps/platform/web/package.json`) lacks a public package export. Its composition root (`AppDesk.tsx`) tightly couples all 25+ internal desk applications.                                                  | Declare a narrow client subpath (e.g. `@codexsun/platform-web/client`) exporting only auth, session, tenant, and company/year coordination. Compose only approved owner routes in cxmobile without desktop desk overhead.                                                                             | Open, M0/M2    |
| A02 | High     | CRM (`crm-request.ts`), Billing (`billing-api.ts`), Chat (`chat.services.ts`), and Ecommerce (`ecommerce-fetch.ts`) each use disparate request helpers, header conventions, and runtime config access.                   | Standardize on one infrastructure transport seam (`cxmobile/native/transport`) that injects required headers (`x-codexsun-session-slot`, `x-tenant-id`, `x-tenant-db`, company/year context) while retaining owner-defined fixed resource services and Zod contracts.                                 | Open, M1/M2    |
| A03 | High     | Browser session attachment and 401 handling depend on monkeypatching `window.fetch` and invoking `window.location.replace` in `apps/platform/web/src/shared/auth/session-expiry.ts`.                                     | Implement native session coordination that attaches scope explicitly to native HTTP requests, detects 401 expiration without page redirection hacks, and preserves clean in-app login transitions without altering browser web behavior.                                                              | Open, M1       |
| A04 | High     | Encrypted HttpOnly session cookies (`session-cookie.ts`) and WebSocket upgrade authentication are not automatically shared between WebView and native networking on mobile OSs.                                          | Verify native-owned protected storage (Android Keystore, iOS Keychain), native HTTP cookie jar persistence, and authenticated native socket upgrade on both physical Android and iOS devices before general screen integration.                                                                       | Open, M1       |
| A05 | High     | Fastify API (`api-url.ts`) rewrites `/api/app/*` to `/*`, while Ecommerce services (`product-information.services.ts`, `featured-card.services.ts`) use `/api/platform/*` paths that rely on Vite/Nginx proxy stripping. | Inventory all active path prefixes and aliases. Normalize client requests through the approved API origin without prefix ambiguity, and ensure backend route contracts handle both direct port and reverse-proxied invocations.                                                                       | Open, M0/M1    |
| A06 | High     | Billing document workspaces (`sales.print.tsx`, `quotation.print.tsx`, `payment.workspace.tsx`) and reports invoke `window.print()`, which fails or misbehaves inside mobile WebViews.                                   | Retain owner document layouts and PDF rendering contracts while adding an authenticated native PDF download, preview, and system share adapter via `@capacitor/filesystem` and `@capacitor/share`.                                                                                                    | Open, M2/M4    |
| A07 | High     | Chat realtime (`chat.services.ts`, `chat.realtime.ts`) opens a browser WebSocket directly to `/chat/realtime` using ambient browser cookie state.                                                                        | Introduce an authenticated native socket transport seam. Validate connection upgrade, message frame decoding, reconnect catch-up, typing/presence events, and revocation on mobile networks.                                                                                                          | Open, M1/M5    |
| A08 | High     | The initial project plan lacked an explicit, end-to-end persisted slice spanning all four applications before broad rollout.                                                                                             | Mandate M2 proof slice on Android and iOS: (1) sign in and select company/year; (2) create CRM enquiry and add comment; (3) create Billing quotation and share PDF; (4) send Chat message and file attachment; (5) save Ecommerce catalog item draft and image; (6) sign out and confirm cache purge. | Open, M2       |
| A09 | Medium   | Chat routes include broadcast channels and optional Telegram integration (`chat.telegram.workspace.tsx`). Billing exposes both customer and supplier summaries alongside detailed statements.                            | Fully enumerate all 6 Billing reports, all 4 Chat conversation kinds (dm, group, channel, broadcast), and optional Telegram settings in the active inventory and verification ledger.                                                                                                                 | Open, M0/M3–M6 |
| A10 | Medium   | Source modules exist without active navigation entries in `AppDesk.tsx`, notably `apps/billing/web/src/modules/opening-balance`.                                                                                         | Classify all modules: Opening Balances has complete backend and frontend code and requires an explicit entry-point resolution in M0; Contact 360 is unfinished and must remain hidden; Storefront cart is local preview only.                                                                         | Open, M0       |
| A11 | High     | Multi-tenant and company/financial year switches could trigger stale query cache leakage or out-of-order responses.                                                                                                      | Establish an explicit query cache key tuple: `[environment, sessionGeneration, tenantId, userEmail, companyId, financialYearId, resource, ...params]`. Cancel in-flight requests and flush scoped caches on context transition.                                                                       | Open, M1/M2    |
| A12 | Medium   | Simple route-level code splitting does not guarantee performance budgets on midrange mobile devices.                                                                                                                     | Establish measurable p95 budgets: initial JS bundle <= 500 KiB gzip, cold launch <= 3.0s, list usability <= 2.5s over 150ms RTT / 10 Mbps, zero background polling leaks, and stream-based transfers for large media.                                                                                 | Open, M2/M7    |
| A13 | High     | Mobile client binaries distributed through app stores remain installed across backend deployments and cannot be rolled back atomically.                                                                                  | Enforce backward-compatible API evolution, monotonic native build numbers, server capability checks, and graceful update-required notifications without destructive client crashes.                                                                                                                   | Open, M0/M8    |
| A14 | High     | The storefront shopping cart in `apps/ecommerce/web/src/modules/storefront/storefront.cart.ts` uses local browser storage without server checkout, order placement, or payment gateway APIs.                             | Delimit staff parity scope to catalog management, variants, image uploading, publishing, and isolated storefront preview. Track customer checkout, payments, and stock reservation under separate future phase EC1.                                                                                   | Open, EC1      |
| A15 | Medium   | Declaring Capacitor plugins in configuration does not prove native capability execution, background push delivery, or camera/file permissions.                                                                           | Establish an explicit native capability matrix with verified fallbacks, runtime permission prompt handling, and physical device test evidence on both Android and iOS.                                                                                                                                | Open, M1/M5/M7 |
