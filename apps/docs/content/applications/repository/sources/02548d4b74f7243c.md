## Domain responsibilities

Shared tenant masters, contact and product identity, organization records, and geographic relationships.

A concrete leaf owns its schema, repository, validation, routes, seeds, and UI. Other apps use public lookup contracts rather than private Core implementations.

## Implementation rules

- Inspect the affected source and public contracts before editing.
- Keep concrete business behavior in its owning leaf or package.
- Preserve authoritative validation, permission checks, and data ownership.
- Add worker, event, or sync roles only when they contain real implemented behavior.
- Keep secrets, generated files, and local runtime data out of source control.
- Run npm commands from the repository root. Write generated output under root `dist`.
- Update this owner documentation when scope, contracts, or supported operations change.

## Unit identity initialization

Keep defaults-v2 as an appended migration after standard-column upgrades.
For new databases only, reserve unit ID 1 for hyphen.
For upgrades, preserve occupied IDs and references. Never relabel a business unit as hyphen to obtain ID 1.
Use exact normalized unit names for defaults and parent mapping. Do not silently equate Pieces, pcs, Numbers, and Nos.
New products use active hyphen by identity. Preserve existing non-null units and require review for conflicting placeholders.

## Company transfer protocol

Keep seed provenance in Company and Default Company owners. Add upgrades as separate tracked steps.
Do not identify a reusable seed by ID 1 or company name alone. Require its owner marker and pristine signature.
Clear seed status when the owner edits a record or Data Bridge confirms its business identity.
Preserve established company IDs, UUIDs, creation metadata, and dependent references.
Do not automatically merge or delete existing companies. Ambiguous identities require reviewed mapping.

## Company branding imports

Expose target branding updates through updateCompanyBrandingForDatabase.
Data Bridge must use the audited target company ID and register the exact target database connection first.
Preserve company identity, creation metadata, and dependent references. Do not copy source IDs to choose the target company.
