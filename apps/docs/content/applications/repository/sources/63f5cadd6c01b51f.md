# Data Bridge

Data Bridge is a Super Admin DevKit for reviewed, queued business-data migration between verified database connections.
Platform owns authentication, active tenant resolution, navigation composition, and queue dispatch.
Data Migration owns external source credentials. Data Bridge uses its public server-side resolver.

## Pages and stages

The sidebar contains Database Connection, Common Tables, Master Tables, Billing Tables, and Report.
Each business group contains Table Mapping, Field Mapping, Import Preparation, Confirm Import, and Results tabs.
The tabs share a persisted session and connection pair. Saved mappings and legacy links remain accessible.

Common Tables owns the common-parent policy. Master Tables owns master and child scope.
Billing Tables discovers installed business tables and excludes runtime history and command queues.
Each group owns its API policy/service/routes and frontend client/workspace in matching module folders.
Technical transfer, snapshot, report, connection, and transport concerns remain in their respective owners.

## Import behavior

Inspect live tables, fields, indexes, defaults, and relationships before mapping.
Support different table and field names through explicit mapping.
Select stable source records and business fields. Resolve source parents through target business identity.
Do not assume equal numeric keys identify the same record across databases.
Prepare target values and audit existing data before confirmation.
Queue approved writes with trusted target context, revisions, locks, schema checks, and transactions.
Preserve existing target conflicts as warnings. Use the separate explicit correction contract for approved updates.

Normal transfers use saved source snapshots and recheck schema and destination values during execution.
Reprepare when source, parents, mappings, or routing change. Correction plans apply stronger fingerprint checks.
Current imports commit per table. Verify complete invoice aggregates after all related tables finish.
There is no single cross-table invoice transaction. Guided transfers require explicit child selection.
Private snapshots and backups never belong in Git.

## Ordered business import

Database Connection has one **Audit and import missing business data** action for the verified pair.
The worker runs Common → Masters → Billing in parent order and verifies invoice children afterward.
Saved verified mappings support different table and field names.
One report has Summary, Common, Masters, Billing, Invoices, and Warnings tabs.
Internal chunk sessions stay inside this report.
Conflicts remain unchanged. Missing mappings and unresolved parents require review.
Commits remain per table. Automatic import includes eligible business children.
Individual guided transfers retain explicit row selection.
Read the API and frontend `business-import/SKILLS.md` files for the operating contract.
