## Required repair findings

### XR01: Replace base64 localStorage with native-protected session handling

Priority: P1. Owner: native session/storage integration.
`client/src/native/storage.ts` defaults to `PersistentSecureStorageAdapter` backed by `window.localStorage`.
It encodes values with `Buffer.from(...).toString("base64")` and stores serialized session/token values.
Base64 is reversible encoding, not encryption or Keychain/Keystore isolation.
`Buffer` is also a Node global, without a demonstrated production WebView implementation.
The test named secure storage uses an in-memory adapter and does not establish native protection or process-restart security.

Replace this default with the approved native session design. Never expose session secrets to browser storage or JavaScript bridges.
Keep a clearly named non-production memory adapter only where tests need it.
Verify absence of secrets from WebView storage, native secret access boundaries, logout, restart, and account isolation.

### XR02: Wire actual owner workspaces into the installed application

Priority: P1. Owner: shell/integration and domain workers.
`client/src/shell/mobile-shell.tsx` mounts `slices/*-view.tsx`, not the parity workspaces under `src/domains`.
For example, `CrmView` shows a prefilled example customer and a create/assign/comment demonstration button.
This is not the complete enquiry list/show/upsert, task, duty, report, settings, and lifecycle application.
Passing route-registry or service tests does not establish that a user can navigate to those screens.

Replace demonstration paths with public owner workspace composition and reachable typed record routes.
Remove fabricated production defaults. Verify each requested workflow from the real application navigation.
Do not accept dead-code domain implementations as mobile feature parity.

### XR03: Prove real native authentication, API prefix, and socket transport

Priority: P1. Owner: native transport and Platform public client contract.
`NativeSessionManager` and `NativeHttpTransport` default to `globalThis.fetch`.
Login does not demonstrate a native-owned cookie jar or a cookie-preserving native transport.
The session manager normalizes configured URLs to origin, dropping an API path such as `/api/app`.
Login can manufacture a random session slot when the server omits one, rather than failing the required server-issued contract.
It models `data.token`, while the reviewed Platform bearer-delivery property is `accessToken`.

`client/src/native/websocket.ts` imports Node `ws` and constructs a cookie from token or the literal `native_session`.
This does not create the server's encrypted session cookie or a working WebView/native socket implementation.
Node test servers accepting these values do not establish compatibility with the real Platform auth layer.

Preserve the configured API base path. Require valid server-issued session state.
Implement the reviewed native HTTP/socket contract and test the actual Platform API without weakening browser protections.
Verify login, restore, expiry, revoke, socket upgrade, media/files, and wrong-tenant denial on target platforms.

### XR04: Restore business ownership instead of duplicating Billing rules

Priority: P1. Owner: supervisor and Billing integration.
`src/domains/billing/calculations.ts`, `opening-balance.ts`, `permissions.ts`, `services.ts`, and `types.ts` duplicate business rules in cxmobile.

Reuse or expose owner public contracts. Remove duplicate authoritative mobile business logic and invented API schemas.
Keep cxmobile composition and transport infrastructure only.
Reconcile endpoint payloads against real owner schemas and verify server-denied operations in disposable tenant fixtures.
