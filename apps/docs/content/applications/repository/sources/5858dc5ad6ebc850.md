## Codeit launch integration

The optional `codeit` catalog entry appears in Tenant Apps and the tenant launcher after activation.
Codeit owns its read-only overview and settings through the public `@codexsun/codeit` package.
Platform composes `/app/codeit/overview` and `/app/codeit/settings` with its tenant activation gate.
The app settings shortcut follows the active Codeit application.
The launch button opens the separate Codeit runtime. Platform does not start or embed that runtime.
Local launch links use `CODEXSUN_CODEIT_WEB_PORT`, default 7070.
Hosted launch links require `CODEXSUN_CODEIT_WEB_URL` at web build time.
Run the normal Platform registry seed for existing databases to receive the catalog row.
See [Codeit](../../devkits/codeit/README.md) for the standalone scope and startup command.

Platform composes Data Bridge's `data-bridge.common-import` Queue Manager processor. Jobs carry the registered target tenant, operator, correlation ID, bounded retry policy, and a run reference. Data Bridge owns parent ordering, row audits, inserts, and combined reports. The Common Tables bulk action requires an enabled queue worker.

Frappe enquiry scheduling honors the selected inbound-only or bidirectional mode.
The inbound interval supports one minute. The scheduler checks due work every ten seconds and
avoids adding another import while one is pending or running for the same tenant and site.
Supported post-save exports request immediate dispatch. The tracked consumer handles those hints. Database workers still claim each job
atomically; Redis delivery uses the selected BullMQ backend. Queue startup also dispatches once.
The first inbound queue job imports history. Later jobs start from the last successful source checkpoint.
The enquiry outbox remains stored while inbound-only mode pauses automatic exports.
See [Frappe](../frappe/README.md) for the migration, source data contract, and verification limits.
Enquiry export retries require `crm.enquiry.update`, Frappe connection management, and enquiry view-all access.
Manual retries create a new outbox correlation ID without changing the record or comment retry identity.
Queue delivery keys include that correlation generation and the persisted attempt count.
Repeated scans reuse one delivery. A manual retry cannot reuse a completed job from an earlier retry cycle.
The optional `@codexsun/platform-api/background` contract composes existing handlers for Worker.
`CODEXSUN_QUEUE_EXECUTION_HOST` selects `platform` by default or the opt-in `worker` executor.
Producer-only Platform keeps API and administration contracts while refusing local job execution.
See [Worker](../worker/README.md) for startup requirements, compatibility limits, and the drain-and-stop cutover.
Platform injects the public Frappe enquiry state reader into CRM after its normal record and sync visibility checks.
Frappe owns source links. CRM owns delivery events. Platform only composes those contracts.

Active, DNS-verified custom domains select their mapped tenant for login and password
recovery. Corporate ID is hidden on those forms. Shared-host login, including
`codexsun.com` and `app.codexsun.com`, still requires it;
unknown hosts and supplied mismatched IDs fail closed. Tenant selection remains server-owned.
Tenant users can sign in with their email or an optional, tenant-unique username.
Administrators manage usernames in the tenant user form; email remains required for recovery.

CRM composes an administrator role ceiling for tenant-wide enquiry and task permissions.
Authorization uses active persisted user-role and role-permission links on every request.
The editable `team-head` role is seeded with label `Team Head`; re-seeding preserves a custom label.
Access Control hides unfinished CRM Contact 360 entries through the CRM public policy contract.

## Redis queue ownership

BullMQ publishers and workers use a CODEXSUN prefix derived from the configured master database identity.
Separate master databases therefore use separate queues even when they share one Redis database.
Every worker delivery carries both the persisted numeric job ID and UUID. Mismatched identities fail before dispatch.
The Redis worker tick republishes pending database records to recover missing deliveries after startup.
Upgrade every worker for the same master database together. Do not purge shared Redis or legacy queues during this change.
See [the delivery verification log](agent/REDIS-DELIVERY-2026-10-24.md).

## Data Bridge account transfer

Platform owns the dedicated app_users credential transfer, target registry resolution, active Super Admin recheck, and User-role assignment.
The transfer copies supported existing PBKDF2 hashes exactly, without generating a new password or returning hashes to the browser.
Existing target accounts remain authoritative. Source roles, elevated privileges, and protected flags are not imported.
Unsupported hashes, schemas, usernames, or missing User roles produce sanitized warnings.
Core, Billing, and CRM public seed contracts establish their User access defaults on the registered target.
App activation and tenant/record scopes remain enforced. Permission grants do not activate applications or bypass entitlements.
Data Bridge persists sanitized account outcomes in a separate Users report tab.

## CRM tenant sync gate

Platform composes CRM/Frappe activation with the Frappe-owned saved connection and Live sync settings.
The CRM capability endpoint returns only an authenticated tenant-scoped Boolean.
Enquiry sync permission remains an additional requirement for enquiry status/history.
Immediate dispatch, relays, import/export requests, and queued workers check this gate.
A disabled queued enquiry/contact/duty delivery retains its pending event and advances only its delivery generation.
It does not consume a remote attempt or change the stable event identity.
This permits safe resume without reusing the completed deferred queue job.

## Queue availability holds

Frappe jobs use a registered Queue Manager readiness check before claiming an attempt.
Pending holds store `held`, `holdReason`, and `resumeAt` in their result and keep `available_at` in the future.
Database workers leave these jobs pending. BullMQ moves the same delivery to delayed with `DelayedError`.
No failure audit or retry attempt is created for a preflight hold.
A transport failure after claim refunds the queue attempt and uses the Frappe-owned availability cooldown.
Business mapping failures still use normal retry and error behavior.
Platform composes the Frappe-owned schedule and health check for imports, exports, contact/enquiry outboxes, SOPs, and duties.
Schedulers and relays check readiness before creating automatic jobs. CRM list reads never ping Frappe.

## Global administration authority

All registered `/admin` routes, including `/api/platform/admin` when mounted with that prefix, require a matching active server-backed Super Admin session.
The root authentication context installs the global guard after session resolution and before request validation or handlers.
Tenant users, including tenant administrators, and staff cannot read or change the global tenant registry, plans, subscriptions, app registry, entitlements, access control, industries, activity, or operational administration.
Client headers, role names, request bodies, and token claims without a matching active server session cannot grant this access.
Unknown stored session user types or access modes fail closed instead of defaulting to Super Admin authority.
Tenant and public routes retain their existing owner authorization. Staff retains its own session surface.
The regression suite executes actual route registrations with signed synthetic tokens and in-memory session/service boundaries. It never contacts a database or a live service.
